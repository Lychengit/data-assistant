# 医生月度绩效报表导出（doctor_perf_excel_report）

## 这个技能做什么

把「本月医生绩效」做成一份 Excel 交回给用户，全程三步：

1. **取名单** → `interface-doctor POST /doctor/list`（不传参，拿到真实医生编号与科室取值）；
2. **查绩效** → `interface-doctor POST /doctor/performance`，对名单里每位医生按 `doctor_id` + `month` + `metric_key` 查一次；
3. **出文件** → 把第 1、2 步的结果整理成一份输入工件，交给本技能自带的固定脚本 `scripts/gen_perf_excel.py` 生成 Excel。

上传按 §18.4.4 切分：**沙箱内没有凭据**（无令牌、无对象存储密钥、无网卡），脚本只把 xlsx 写到沙箱里；
真正的上传由**平台侧**经 `interface-doctor POST /doctor/export/upload`（写接口，W1–W3）完成：
它写入对象存储、登记工件血缘，并回一个**短期有效**的下载链接。

## 上传怎么触发（照做，否则流程一定卡死）

上传是**写操作**，平台会在真正执行前**自动弹一张确认卡**给用户。所以：

- 生成 xlsx、拿到 `content_base64` 之后，**在同一个回合里直接调用** `iface_doctor_export_upload`
  （参数 `file_name` 与 `content_base64`，调用一次就够）。**不要**先写一段话问用户「要不要上传」。
- **绝对不要**说「请回复『确认执行』，我再上传」这类话。确认动作**只发生在平台弹出的确认卡上**，
  文字确认不会触发任何东西：用户回了也没有卡，只会白白多耗一轮。
- 一个回合只调**一次**上传。只有在确认卡被用户**拒绝**、或上传本身报错之后，才停下来把原因讲清楚并等指令；
  不要自己反复重试同一个写操作。
- 你的职责是**发起**这次写操作，然后交给平台的确认事件去推进。

## 在沙箱里怎么生成文件

沙箱命令要经过宿主机的 `docker exec sh -c <命令>`。含中文的内容一律走 base64 字面量
（base64 只有 `A-Za-z0-9+/=`，整条命令是纯 ASCII，不经过任何引号 / 编码环节）：

```
python3 /workspace/skills/doctor_perf_excel_report/scripts/gen_perf_excel.py \
  --data-base64 '<B64>' --output /workspace/out/perf.xlsx
```

脚本会往标准输出打一行 JSON：`{"ok":true,"output":"/workspace/out/perf.xlsx","rows":N,...}`。
**确认 `ok` 是 `true`，并记下 `output` 这个路径**——下一步要用它。

## 上传：只给路径，不要抄 base64（照做）

上传**不要**在参数里塞 `content_base64`，也不要打印或复制那份 base64。只给一个**路径**：

```
iface_doctor_export_upload(
    sandbox_path = "/workspace/out/perf.xlsx",   # 就是上一步脚本的 output
    file_name    = "医生绩效表_2026-08.xlsx",
    content_type = "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
    artifact_name= "2026年8月医生绩效表（门诊人次）"
)
```

**不要**因为 schema 里仍然列着 `content_base64` 就去填它：只要参数里给了 `sandbox_path`，
宿主代理会以路径为准把字节读出来覆盖掉它（2026-09-27 起 `required` 里也不再要它）。
万一调用被拒、理由正是「缺少 content_base64」（说明运行时是旧版本），填一个随便的非空占位符
（例如 `"placeholder"`）即可——那份字节会被 `sandbox_path` 的真实内容覆盖，不会影响上传结果。

宿主代理会按这个路径把文件读出来、填好内容再上传。**为什么必须这样**：base64 是 8.5KB 的不透明
长串，靠模型原样抄写**实测会翻车**（2026-09-27：模型打印了截断预览，再凭碎片拼出一份 224 字节的
坏 xlsx——上传成功、链接有效、文件打不开）。路径短、可核对，字节交给平台搬。

生成完文件就**直接调用**它，不要用文字征求确认（确认卡由平台弹，见上一节）。
## manifest 怎么写（照抄这份就行）

`manifest.json` **只必填三项**，这份技能包就是按最小集写的：

```json
{
  "id": "doctor_perf_excel_report",
  "name": "医生月度绩效报表导出",
  "description": "一句话说清它做什么——这句会下发给模型，用来判断什么时候该用它",
  "script": { "path": "scripts/gen_perf_excel.py", "data": "none", "timeoutSeconds": 120 }
}
```

- **`script` 块只有脚本类技能要写**（写了它就是脚本技能，不用再写 `kind`）：`path` 是包内路径、
  `data` 只能是 `none`（脚本自己不取数，数据由宿主喂）/ `via_host`（经宿主代调接口取数）、
  `timeoutSeconds` 在 (0,300]。
- **版本可以不写**：不写就按包内容哈希自动生成（`0.0-<内容前 8 位>`）。想让人看懂就自己写，如本包的 `1.1.0`。
- **接口不写在包里**：上传后在管理端「技能包 M3 → 已登记技能 → 绑定接口」里勾。包内写 `boundRoutes`
  也可以（发布时按它整体替换绑定），但**不写才是常态**——不写意味着「绑定不归这个包管」，
  重新发布不会抹掉页面上配好的那份；显式写 `[]` 才是清空。
- **打包**：`manifest.json` 放在压缩包最外层最省事；连文件夹一起压缩也行（「右键 → 压缩文件夹」
  会套一层目录名），平台会自己认出那一层——包内路径（`script.path` 等）一律相对包根写。
- `params` / `resources` / `exports` / `status` 都可以不写：`params` 与 `resources` 只影响平台生成的
  说明内容，`exports` 是评审时给人核的导出字段清单，`status` 没人读。

## 参数

| 参数 | 必填 | 说明 |
| -- | -- | -- |
| `month` | 是 | `YYYY-MM`。**不要自己算月份**（跨年很容易错），由平台按公司口径解析后传入 |
| `metric_key` | 否 | 指标键，默认 `outpatient_visits`；必须命中口径字典，否则接口服务会拒绝 |

## 取数口径（照做，不要即兴）

- **`dept_code` 的真实取值是中文科室名**（`心内科` / `呼吸科` …）。要按科室过滤，先调 `doctor_list`（不传参）
  看真实取值，**不要**把「心内科」自己翻成 `cardiology`——那会拼出一个命中不了任何行的条件，
  结果看起来像「这个月没数据」。
- 本技能**不传 `dept_code`**：目标是「本月全部医生」，不是某个科室。
- 某位医生这个月没有绩效行，是**正常情况**（不是错误）：名单里有、绩效查回空，就在报表里留空并在
  摘要里写明「N 位医生本月无绩效数据」。不要为了让表格好看而补 0——0 和「没有数据」在绩效口径里是两件事。
- 交给脚本的输入工件里，`doctors` 就是**名单**（无数据的医生也要放进去，`metric_value` 写 `null`），
  `missing` 只写这些医生的编号**作为标注**。`missing` 是 `doctors` 的子集，别再把人头数加第二遍。

## 产出

- 一份 `.xlsx`（工作表 `绩效明细` + `口径说明`）；
- 一条工件登记（`artifact` 表：编号 / 名称 / 大小 / 归属 / 存储定位 / 到期时间）；
- 一个**短期有效**的下载链接（默认 30 分钟；对象保留 7 天）。

## 不该做的事

- 这个技能**自己不再调** `/doctor/export/upload`：上传是**平台侧**的动作（宿主代理持令牌经网关代调）。
- 上传能不能走通，取决于调用人的角色对这个接口有没有权限：要么直配（`role_api`），要么把写接口绑进技能
  （`skill_api`，2026-09-27 起允许）后由技能带出。写操作无论走哪条，执行时都要一次确认卡（`confirmId`，§19.9）。
- 不在脚本里联网、不读环境变量里的密钥：脚本拿到的只有输入工件与一个可写目录。
- **不用文字征求写操作的确认**（见「上传怎么触发」）：确认卡是平台弹的，文字问确认等于把流程卡死。
- 不在确认卡被拒绝之前反复重试上传：那是一次写操作，重试只会一次次撞同一个闸口。
